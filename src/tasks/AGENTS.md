# 拍卖功能约束

本文约束 `src/tasks/AutoBidAuctionTask.py` 中的拍卖功能及其后续拆分代码, 并约束对应的拍卖测试。其他任务仍遵守仓库根目录 `AGENTS.md`。若拍卖实现迁入子包, 本文继续适用于该子包, 直到在新位置建立更具体的约束文件。

## 职责范围

- 拍卖功能负责异环游戏内自动竞拍任务: 配置声明、拍卖界面识别、匹配与确认、出价及重试、结算、低保领取、可选辅助操作、藏品出售和掉线回场。
- 当前任务入口是 `AutoBidAuctionTask`, 继承 `NTEOneTimeTask` 与 `BaseNTETask`; 任务注册位于 `src/config.py`。保持现有任务标识、配置键、默认值及旧用户配置兼容。
- 轮次状态机和整体流程编排归任务入口负责。拍卖专属的界面框、OCR 规则、解析、低保、仓库出售等能力归拍卖域; 不扩散到通用 mixin。
- 不在拍卖任务中实现通用窗口控制、截图/OCR框架、角色战斗、场景全局状态或其他任务业务。发现可复用需求时先确认其确属跨任务能力, 再放入既有公共层。
- 不把 `docs/zh-CN/development/auction-layering.md` 所述目标包结构当作现状。该文档是未实施提案; 代码迁移须按小阶段完成并保持各阶段可运行。

## 代码与命名规范

- 遵守仓库 Python 规范: Python 3.12+, ruff 行宽 100、双引号、导入排序; 优先复用 ok-script API 和任务基类。
- 任务类使用 `AutoBidAuctionTask` 命名; 拍卖领域类型使用带 `Auction` 语义的 PascalCase 名称; 配置键与 UI 文案遵循现有稳定命名, 不为内部重构随意更名。
- OCR 模式使用语义清楚的 `RE_*` 常量; 相对屏幕区域使用 `BOX_*` 常量, 并经 `AuctionBoxes` 一次性构造后传给流程方法。不要将 OCR 裁框混入 `src/scene/PanelPosition.py` 或通用 `PositionMap`。
- 领域流程方法沿用 `_stage_*`、`_read_*`、`_parse_*`、`_sell_*` 等可检索前缀。纯解析、价格计算和状态判定应保持无 IO, 能用静态/模块纯函数表达时不依赖任务初始化。
- 状态、配置或结果结构优先使用枚举、冻结数据类和明确类型; 不新增含义不清的布尔参数、松散字典或跨阶段共享的隐式状态。
- 带超时与重试的循环必须有明确截止时间、轮询间隔和退出条件; OCR 不确定、价格无效、界面状态未知时按保守路径处理, 不提交未经验证的价格或重复点击。
- 保持输入节奏可中断。只能通过项目现有的截图/OCR、普通键鼠、窗口和系统输出接口交互; 不使用进程注入、内存读取、Hook 或游戏内部接口。
- 修改用户可见配置、默认值或说明时, 同步检查任务卡说明及 `src/config.py` 注册; 配置键变更须有兼容迁移, 不得静默丢弃用户值。

## 目录组织与依赖方向

当前实现与测试位置:

- `src/tasks/AutoBidAuctionTask.py`: 唯一拍卖任务入口及当前领域实现。
- `tests/TestAutoBidAuctionTask.py`: 拍卖任务及领域行为测试。
- `docs/zh-CN/development/`: 拍卖分层设计和实现说明。

若后续确有维护收益并实施拆分, 使用 `src/tasks/auction/` 作为拍卖专属包, 可按职责放置 `options.py`、`layout.py`、`sell.py`、`welfare.py`、`screens.py` 等模块。拆分应遵循依赖方向: 声明/布局契约在底层, 领域能力依赖契约和框架原语, `AutoBidAuctionTask` 保留轮次编排。不要为了套用目录而搬动代码, 不引入 `AuctionContext`、通用屏幕基类或仅转发调用的抽象层。

如未来测试规模需要按领域拆分, 在 `tests/` 下采用 `TestAuction<领域>.py` 文件, 并保持可由 unittest discover 收集; 在当前单文件结构下继续把用例放在 `tests/TestAutoBidAuctionTask.py`。避免为了目录对称而新增空包。

## 接口约定与模块边界

- `src/config.py` 负责任务注册与应用级配置入口; `AutoBidAuctionTask` 使用框架注入的配置、日志、截图、OCR、点击和任务生命周期 API, 不复制这些基础设施。
- 拍卖内部方法以任务类私有方法和拍卖专属数据类型为主。其他任务不得调用 `_` 私有方法或依赖 `AuctionBoxes` 的内部字段; 跨模块共享前应先定义稳定、最小的公开接口并配套文档和测试。
- 传递界面区域时使用 `AuctionBoxes`; 传递结算观测时使用 `PostRoundState`; 轮次阶段使用 `AuctionState`。新增字段要说明缺省/未知含义, 不将“未观测”混同为 `False`。
- 保留框架基类约定的任务生命周期、配置 schema 和用户可见任务行为。不得从拍卖模块修改全局截图/OCR语义、窗口输入策略、战斗或其他任务状态。
- 与月卡弹窗等其他功能交互时仅调用已有公共能力, 并为失败/无结果保留可恢复路径; 不让拍卖私有规则进入通用弹窗处理器。
- 任务在大世界、主界面、拍卖流程中断或弹窗阻塞等状态下应识别当前画面后再采取动作。识别失败、超时、放弃和异常均须有限退出, 不能在错误界面持续输入。

## 调试与热重载

- 已核实 (2026-09-28, ok-script `ok/core/task_manager.py`): 调试热重载只监视并 reload 任务类源文件 `src/tasks/AutoBidAuctionTask.py`; `importlib.reload` 不会重新执行 `sys.modules` 中已缓存的 `src/tasks/auction/*` 子模块, 子包目录也不在文件监视范围内。
- 因此调试拍卖任务时, 编辑 `auction/` 子包后必须重启应用才能加载新代码; 只触发任务入口文件的热重载并不会带上子包的新实现, 静默运行旧代码比报错更难排查。不要假设子包会自动热重载。

## 测试约束

新增或修改拍卖测试前, 必须先读仓库 `tests/TESTING.md`; 本节补充拍卖特有覆盖要求。

### 覆盖范围

- 核心流程: 任务配置装配和配置可达性; 匹配、确认、出价、结算的状态转换; 单轮成功/失败及后续轮次; 结算后的观察与收尾。
- 价格与 OCR 边界: 半角/全角数字及分隔符、空值/噪声、残缺或分组异常数字、价格上下限、估价缺失、舍入、边界屏幕区域和输入后价格校验。错误或不完整读数不得被当作有效低价。
- 出价配置: 固定/自定义/估价模式、自动加价模式与回合数、指定回合价格、缺省值和非法配置; 包括配置键在各模式下仍可达且不误隐藏无关选项。
- 低保与售卖: 领取次数解析、每日额度与日期切换、弹窗关闭/领取失败; 各售卖模式、品质筛选、满仓与非满仓、失败升级/成功复位、超时及售卖结果不确定。
- 恢复与异常: 匹配/确认/出价/结算超时, 点击失败, OCR 空结果或误识别, 阻塞弹窗, 掉线回到大世界后的有限回场, 回场预算耗尽, 未知界面及中断。每个新增失败分支和异常恢复路径至少有一条有判别力的用例。
- 配置兼容和用户可见行为: 默认值、旧配置缺键/旧值、说明文案与配置 schema 一致; 任务名/注册标识不变。

用例应锁定可观察结果: 返回状态、配置/价格结果、计数器或任务状态变化、是否采取必要输入、是否有限退出。不得只断言日志、私有方法调用顺序或测试自行推导的常量关系。

### 组织与命名

- 当前拍卖用例放入 `tests/TestAutoBidAuctionTask.py`; 按被测单元分成聚焦的 `unittest.TestCase` 类, 类名使用 `TestAuction<领域>`。
- 测试方法使用 `test_<行为>_<预期结果>`; 每个用例写简短 docstring 说明所保护行为的重要性。多组同类输入使用 `subTest`。
- 解析/计算优先直接测纯函数; 任务流程通过 `__new__` 或既有测试 helper 构造轻量桩对象, 仅 mock OCR、截图、点击、时间等 IO 边界, 保持真实控制流。
- 所有 deadline、轮询与重试使用假时钟; 测试不得真实等待、依赖游戏窗口/截图/音频/网络, 也不得写入仓库用户数据路径。
- 每个测试应能单独运行且能在全量 discover 中运行; 在 `tearDown` 恢复 patch、单例及其他共享状态。新增源文件/测试文件遵循仓库 `Test*.py` 风格和 UTF-8 编码。

### 通过标准

- 定向命令通过: `.\.venv\Scripts\python.exe -m unittest tests.TestAutoBidAuctionTask`。
- 全量 `.\.venv\Scripts\python.exe -m unittest discover -s tests -p "*.py"` 通过, 不出现仅在全量运行时产生的状态污染。
- 新增回归用例应能区分修复前后的行为; 对 bug 修复按 `tests/TESTING.md` 做变异验证, 将修复反向改回时对应测试应失败。
- 若拍卖代码拆分, 除新测试通过外, 原有拍卖行为断言不得为迁就新结构而删除或弱化; 配置和任务外部契约保持兼容。
- 依赖真实游戏环境的人工验证不得替代上述纯逻辑/桩测试; 若某项确实只能人工确认, 在交付说明里写清验证范围。
