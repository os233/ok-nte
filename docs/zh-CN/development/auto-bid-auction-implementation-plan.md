# AutoBidAuctionTask 分阶段实施计划

## 实施原则

本计划将重构拆成可独立审查和验证的阶段。优先保持现有行为、配置和框架调用契约不变；一次只搬迁一类职责，等模块边界稳定后再考虑整理控制流。

任务当前由 `src/config.py` 按 `src.tasks.AutoBidAuctionTask.AutoBidAuctionTask` 注册。此注册路径、任务类和用户配置键应在整个重构过程中保持兼容。

## 阶段 0：建立基线

**优先级：P0，开始改代码前完成。**

### 目标

确认当前工作区和测试基线，记录需要保留的行为与状态契约。

### 关键任务

1. 检查工作区变更，确认不会覆盖已有修改。
2. 阅读 `tests/TESTING.md`，遵循项目测试搭建、时钟控制和副作用复位规范。
3. 运行拍卖任务定向测试并记录通过数量和已有失败。
4. 列出任务注册路径、任务名、配置键/默认值、配置面板行为，以及外部或测试直接访问的类常量和方法。
5. 建立状态清单，记录 `_post_round_state`、`_inventory_stuck`、`_sell_failures`、低保日计数和 `last_bid_price` 的读写位置与重置时机。

### 验收标准

- 有可复查的测试基线记录，能区分已有失败与新增回归。
- 配置契约和直接引用点已经列出。
- 关键实例状态的所有者和生命周期明确。

## 阶段 1：抽取配置与 UI 区域定义

**优先级：P1。**

### 目标

先拆低耦合定义，建立 `auction` 包结构并验证新导入路径。

### 关键任务

- 新建 `src/tasks/auction/` 包。
- 将默认配置、控件类型、条件可见配置和说明迁至 `options.py`。
- 将 `AuctionBoxes` 与拍卖区域定义迁至 `layout.py`。
- 在 `AutoBidAuctionTask` 保留 `CONF_*`、`BOX_*` 等兼容引用。
- 保持 `src/config.py` 的任务注册路径不变。

### 验收标准

- 默认配置键和值、面板控件和条件可见项与基线一致。
- `AuctionBoxes` 各字段仍映射至相同 UI 区域。
- 任务可通过原路径导入和注册。
- 拍卖任务定向测试通过。

本阶段只搬声明，不同时调整配置文案、坐标或识别规则。

## 阶段 2：拆分价格策略与输入流程

**优先级：P2。**

### 目标

分离纯价格规则与 OCR/输入副作用，使价格逻辑更容易独立理解和验证。

### 关键任务

1. 先迁移纯逻辑：数值解析、出价列表解析、价格计算、加价模式、指定回合价格和键盘按键序列。
2. 再整理依赖 OCR 的估价读取，以及依赖输入 API 的数字键盘操作和结果校验。
3. 明确策略输入和输出，例如配置值、轮次、资产/估价观测如何转为目标价格。
4. 保持原有舍入、无效配置回退、OCR 重试和出价重试规则。

### 验收标准

- 各出价模式对应价格与基线一致。
- 无效配置仍按原行为校验、告警或回退。
- 按键序列和输入结果校验保持一致。
- 定向测试通过；纯价格规则能通过新模块接口验证。

不要在同一阶段调整价格策略或输入节奏。

## 阶段 3：迁移藏品出售能力

**优先级：P3，需重点控制行为风险。**

### 目标

将仓库出售作为完整业务边界迁移，保留跨轮状态和异常收尾语义。

### 关键任务

- 一起迁移出售模式判定、间隔策略、仓库操作、品质筛选、出售价值校验和失败升级。
- 明确模块接口所需的区域、deadline、品质清单、满仓状态和状态读写。
- 保留“明确失败”与“超时导致结果未知”的区别。
- 保留出售中断后关闭仓库的清理行为。
- 保留 `_inventory_stuck`、`_sell_failures` 的跨轮含义及清零条件。

### 验收标准

- 满仓、非满仓、定期出售和不出售行为与基线一致。
- 低保阶段选择的出售品质不变。
- 出售失败升级、超时、成功清零等用例通过。
- 出售异常后仓库与品质选择状态能按原行为复位或安全恢复。

## 阶段 4：迁移低保与结算后处理

**优先级：P4。**

### 目标

整理结算观测和低保领取边界，并保留其与出售策略的显式连接。

### 关键任务

- 迁移低保弹窗打开/关闭、领取、次数读取和跨日重置。
- 保留次数读数失败时的保守行为。
- 明确满仓观测、资产观测和低保领取的执行顺序。
- 使用清晰结果传递观测值与低保阶段信息，避免出售模块重复读取或重复决策。

### 验收标准

- 次数上限、弹窗关闭失败、读数缺失和跨日重置行为与基线一致。
- 低保领取超时不会把已完成的拍卖轮次误记为失败。
- 结算观测失败时，后续出售仍按原逻辑补测或跳过。

## 阶段 5：迁移掉线回场与弹窗恢复

**优先级：P5。**

### 目标

集中回场和遮挡恢复能力，但继续由任务状态机决定调用时机。

### 关键任务

- 迁移世界界面探测、返回拍卖入口和入口卡片查找。
- 迁移阻塞弹窗恢复逻辑。
- 确认回场配额由单轮共享，阶段重试不会意外重置配额。
- 保持原有局部等待预算和整轮 deadline。

### 验收标准

- 大世界启动、拍卖中掉线、回场失败和配额耗尽行为与基线一致。
- 回场失败仍进入既有异常处理路径。
- 计时相关用例确认局部超时与轮次 deadline 未重置或绕过。

## 阶段 6：复查状态机与运行时加载

**优先级：P6，最后进行。**

### 目标

能力模块稳定后，评估任务编排是否需要小幅整理，并确认调试加载行为。

### 关键任务

- 复查 `do_run()`、`_run_single_round()` 和 `_exec_auction_round()` 的轮次及阶段职责。
- 只在存在明显重复或理解困难时简化编排；不要借拆分之名重写状态机。
- 检查调试运行时是否会重载 `auction/` 子模块，不假设新增子包会自动热重载。
- 确认任务类和配置的加载路径保持不变。

### 验收标准

- 状态转换、重试次数、轮次统计和异常行为与基线一致。
- 新模块无循环导入。
- 调试时确认修改子模块后实际加载了新代码；若不支持热重载，则按项目调试流程重启任务或应用。

## 每阶段验证流程

每个阶段结束后：

1. 检查 diff，确认只包含当前阶段的职责搬迁。
2. 运行拍卖任务定向测试：

   ```powershell
   .\.venv\Scripts\python.exe -m unittest tests.TestAutoBidAuctionTask
   ```

3. 对修改过的 Python 文件做语法检查：

   ```powershell
   .\.venv\Scripts\python.exe -m py_compile path\to\file.py
   ```

4. 检查导入方向和循环依赖，确认拍卖专属状态没有扩散到通用 mixin。
5. 对影响输入、计时或界面的改动，记录人工验证覆盖范围。
6. 阶段验收通过后再开始下一阶段，便于定位回归来源。

若新增或修改测试，先阅读 `tests/TESTING.md`。不应为了迁移而弱化既有测试断言。

## 全部阶段完成后的检查

- 运行仓库完整 unittest 套件。
- 核对任务配置、任务发现、原有配置读取和调试入口。
- 检查各模块职责与导入方向，确认没有仅为降低行数而引入的间接层。
- 对真实界面依赖的行为说明人工验证范围。

完整测试命令：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "*.py"
```

## 建议的实际起步顺序

先完成阶段 0，记录测试与契约基线；随后只做阶段 1 的 `options.py` 和 `layout.py` 搬迁。阶段 1 验收通过后再处理价格规则。不要一开始就改出售逻辑或轮次状态机。
